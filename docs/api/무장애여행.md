# 한국관광공사_무장애 여행 정보 API 분석

## 기본 정보

- 데이터 포맷: JSON / XML (`_type=json`)
- 공통 필수 파라미터: `serviceKey`, `MobileOS`, `MobileApp`
- 반려동물동반여행 API와 `contentid`로 장소 연결 가능 (핵심 장점)

---

## 엔드포인트 목록 및 활용 계획

### ✅ 주요 활용 엔드포인트

#### 1. `GET /detailWithTour2` — 무장애 정보 조회 (핵심)
contentId 기준으로 해당 장소의 무장애/접근성 상세 정보를 조회.
반려동물동반여행 API의 contentid와 동일한 키로 연결 가능.

**요청 파라미터**: `contentId` (필수)

**응답 필드**

| 필드 | 설명 | 서비스 활용 |
|---|---|---|
| contentid | 콘텐츠ID | 반려동물 API contentid와 연결 키 |
| stroller | 유모차 정보 | 반려견 유모차 접근성 (펫-워크 지수) |
| wheelchair | 휠체어 정보 | 이동 편의성 (펫-워크 지수) |
| parking | 주차 정보 | 주차 접근성 (펫-워크 지수) |
| route | 이동 경로 정보 | 경로 접근성 |
| restroom | 화장실 정보 | 장애인 화장실 여부 |
| elevator | 엘리베이터 정보 | 수직 이동 편의 |
| exit | 출입구 정보 | 출입구 접근성 |
| publictransport | 대중교통 정보 | 교통 접근성 |
| helpdog | 안내견 동반 정보 | 안내견 전용 (반려견과 무관) |
| guidesystem | 안내 시스템 | - |
| auditorium | 강당 정보 | - |
| room | 객실 정보 | 숙박 장소에서 활용 |

> `helpdog`은 안내견(시각장애인 보조견) 전용으로, 일반 반려견 정책과 혼동 주의

---

#### 2. `GET /areaBasedList2` — 지역기반 관광정보 조회
무장애 여행 정보가 등록된 장소 목록 조회. 이 API에 등록된 장소만 `detailWithTour2` 조회 가능.

**주의:** 이 API의 `lDongRegnCd`와 `lclsSystm1`이 필수 파라미터로 표기됨 (반려동물 API와 다름)

**응답 필드**: 반려동물동반여행 API의 `/areaBasedList2`와 동일 구조
(contentid, title, addr1, mapx, mapy, tel, firstimage 등)

---

#### 3. `GET /areaBasedSyncList2` — 무장애 여행정보 동기화 목록 조회
DB 동기화 시 변경된 콘텐츠 감지에 활용. `oldContentid` 필드로 ID 변경 추적 가능.

| 필드 | 설명 |
|---|---|
| showflag | 콘텐츠 표출 여부 (1=표출, 0=비표출) |
| oldContentid | 이전 contentid (ID 변경 추적) |

---

#### 4. `GET /detailIntro2` — 소개 정보 조회
무장애 API에서도 동일한 `/detailIntro2` 제공. 반려동물동반여행 API와 동일한 필드 구조.
단, 무장애 등록 장소의 `chkbabycarriage` 등 접근성 관련 필드 보완 가능.

## 펫-워크 지수 접근성 항목 매핑

| 펫-워크 지수 평가 항목 | 활용 필드 | 출처 |

| 휠체어/경사로 이동 편의 | wheelchair, route | /detailWithTour2 |
| 장애인 화장실 | restroom | /detailWithTour2 |
| 주차 편의 | parking | /detailWithTour2 |
| 엘리베이터 | elevator | /detailWithTour2 |
| 출입구 접근성 | exit | /detailWithTour2 |

## 반려동물 API와의 연계 구조

```
반려동물동반여행 API /areaBasedList2
  └── contentid
        └── 무장애 API /detailWithTour2 (contentId 동일)
              └── stroller, wheelchair, parking, route 등 접근성 정보
```

contentid가 공통 키이므로 1:1 매핑 가능. 단, 무장애 정보가 등록된 장소만 데이터 존재.

## 갭 분석

| 필요 정보 | 문제 | 해결 방안 |
|---|---|---|
| 모든 장소의 접근성 정보 | 무장애 등록 장소만 조회 가능 | 등록되지 않은 장소는 접근성 항목 UNKNOWN 처리 |
| stroller 필드 값 형식 | 텍스트 서술형으로 추정 | 텍스트 파싱 또는 존재 여부(null 체크)로 이진 판단 |
| 반려견 유모차와 일반 유모차 구분 | 구분 불가 | stroller 데이터 존재 여부로 접근성 판단 |

---

## DB 적재 전략

```
1. /areaBasedList2로 강릉/속초/양양 무장애 등록 장소 contentid 목록 수집
2. 각 contentid로 /detailWithTour2 호출하여 접근성 필드 저장
3. 반려동물 API의 장소 DB에 contentid 기준으로 접근성 정보 조인
4. 무장애 정보 없는 장소는 접근성 항목 null/UNKNOWN 처리
```
