# 한국관광공사_반려동물_동반여행_서비스 API 분석

## 기본 정보

- 데이터 포맷: JSON / XML (`_type=json` 파라미터로 JSON 응답)
- 공통 필수 파라미터: `serviceKey`, `MobileOS`, `MobileApp`

---

## 엔드포인트 목록 및 활용 계획

### ✅ 주요 활용 엔드포인트

#### 1. `GET /areaBasedList2` — 지역기반 관광정보 조회
장소 목록 수집의 핵심 엔드포인트. 지역코드 + 시군구코드로 필터링.

**요청 파라미터 (주요)**

| 파라미터 | 설명 | 비고 |
|---|---|---|
| areaCode | 지역코드 | 강원도 = 32 |
| sigunguCode | 시군구코드 | 강릉/속초/양양 코드 필요 |
| contentTypeId | 관광타입 | 12/14/28/32/38/39 |
| arrange | 정렬 | A=제목순, C=수정일순, D=생성일순 |

**응답 필드**

| 필드 | 서비스 매핑 |
|---|---|
| contentid | 내부 placeId 연결 키 |
| contenttypeid | 장소 유형 분류 기준 |
| title | 장소명 |
| addr1, addr2 | 주소 |
| mapx, mapy | 경도(WGS84), 위도(WGS84) |
| tel | 전화번호 |
| firstimage | 대표 이미지 URL |
| firstimage2 | 썸네일 이미지 URL |
| cat1, cat2, cat3 | 대/중/소 분류 코드 |
| areacode, sigungucode | 지역/시군구 코드 |
| createdtime, modifiedtime | 생성일, 수정일 |

---

반려견 동반 조건/유의사항/시설의 핵심 엔드포인트. contentId로 개별 조회.

**요청 파라미터**: `contentId` (필수)

**응답 필드**

| 필드 | 설명 | 서비스 활용 |
|---|---|---|
| acmpyNeedMtr | 동반 필요 사항 | 반려견 동반 조건 (목줄, 케이지 등) |
| acmpyPsblCpam | 동반 가능 반려동물 | 동반 가능 종류 표시 |
| acmpyTypeCd | 동반 유형 코드 | 동반 방식 분류 |
| relaAcdntRiskMtr | 사고 위험 사항 | 반려견 유의사항 |
| relaPosesFclty | 보유 시설 | 이용 가능 시설 |
| relaFrnshPrdlst | 구비 용품 목록 | 시설 내 제공 용품 |
| etcAcmpyInfo | 기타 동반 정보 | 기타 유의사항 |
| relaPurcPrdlst | 구매 용품 목록 | 현장 구매 가능 용품 |
| relaRntlPrdlst | 임대 용품 목록 | 현장 임대 가능 용품 |

#### 6. `GET /locationBasedList2` — 위치기반 관광정보 조회
좌표 + 반경(m)으로 주변 장소 조회. 대체 장소 추천, 주변 응급 시설 탐색에 활용.

**필수 파라미터**: `mapX`(경도), `mapY`(위도), `radius`(최대 20,000m)

응답에 `dist` 필드(거리, 단위: m) 포함.

---

#### 7. `GET /petTourSyncList2` — 동기화 목록 조회
`showflag` 필드로 콘텐츠 표출 여부 확인 가능. DB 동기화(초기 적재, 업데이트 감지)에 활용.

## contentTypeId → 서비스 장소 유형 매핑

| contentTypeId | cat3 | 관광공사 분류 | 서비스 PlaceType |
|---|---|---|---|
| 32 | - | 숙박 | STAY |
| 39 | A05020900 제외 | 음식점 (한식/양식/일식 등) | FOOD |
| 39 | A05020900 | 카페/전통찻집 | WORK_PLACE |
| 12 | - | 관광지 | TOUR |
| 14 | - | 문화시설 | TOUR |
| 28 | - | 레포츠 | TOUR |
| 38 | - | 쇼핑 | TOUR |
| - | - | 동물병원 | HOSPITAL → GWTO PC05 |
| - | - | 걷기/산책 코스 | WALK → 두루누비 API |

### 카페 분류 코드 확인 완료
```
cat1 = A05        (음식)
cat2 = A0502      (음식점)
cat3 = A05020900  (카페/전통찻집)  ← WORK_PLACE 수집 기준
```

WORK_PLACE 장소 조회 시 `/areaBasedList2`에 아래 파라미터 사용:
```
contentTypeId=39 & cat1=A05 & cat2=A0502 & cat3=A05020900
```

FOOD 장소 조회 시 cat3=A05020900 제외하고 조회하거나, contentTypeId=39 전체 조회 후 서버에서 cat3 기준으로 분리.

## 갭 분석 (이 API만으로 해결 안 되는 항목)

| 필요 정보 | 문제 | 해결 방안 |
|---|---|---|
| 반려견 크기 제한 (SMALL/MEDIUM/LARGE) | 직접 필드 없음, 텍스트에 포함 가능성 있음 | `acmpyNeedMtr` 텍스트 파싱 또는 내부 관리자 입력 |
| HOSPITAL | 이 API 미제공 | GWTO PC05 (동물병원) 데이터 활용 |
| WALK (산책 코스) | 이 API 미제공 | 두루누비 API |
| 예측 혼잡도 | 이 API 미제공 | 관광지 집중률 방문자 추이 예측 API |
| 무장애/접근성 상세 | chkbabycarriage 외 상세 없음 | 무장애 여행 정보 API |
