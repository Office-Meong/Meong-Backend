# 오피스멍 백엔드 구축 방향

---

## 1. 데이터 전략: 사전 배치 적재 (Pre-load) 방식 확정

외부 OpenAPI를 실시간으로 호출하지 않고, **배치로 사전 수집하여 자체 DB에 저장**한 뒤 앱 요청에는 DB를 응답한다.

### 이유

| 판단 기준 | 설명 |
|---|---|
| 데이터 변경 빈도 | 장소 정보(운영시간, 반려견 조건)는 주 1회 이하로 변경됨 |
| 점수 계산 복잡도 | 펫-워크 지수 = 여러 소스 + Haversine 거리 계산 → 실시간 불가 |
| 응답 속도 | 외부 API 호출 시 수백 ms 지연 → DB 조회(10ms 이하)와 비교 불가 |
| 외부 API 의존성 | 실시간 방식은 외부 API 장애 = 서비스 장애 |
| 관광지집중률 구조 | API가 30일치를 한 번에 내려줌 → 배치가 자연스러움 |

### 배치 주기

| 배치 | 주기 | 대상 |
|---|---|---|
| 장소 수집 (KTO + GWTO) | 주 1회 (새벽 3시) | places + pet_conditions + operations + scores |
| 혼잡도 수집 | 매일 새벽 2시 | congestion_forecasts (30일치) |
| 두루누비 수집 | 월 1회 | walk_courses |
| 무장애여행 수집 | 월 1회 | place_accessibility |

## 2. REST API 목록

### 인증 (Auth)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/auth/kakao` | 카카오 로그인 (인가코드 → JWT 발급) |
| POST | `/api/v1/auth/refresh` | Access Token 재발급 |
| POST | `/api/v1/auth/logout` | 로그아웃 (Refresh Token 만료) |

### 사용자 (User)

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/v1/users/me` | 내 프로필 조회 |
| DELETE | `/api/v1/users/me` | 회원 탈퇴 (soft delete) |

### 반려견 프로필 (Dog)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/dogs` | 반려견 프로필 등록 |
| GET | `/api/v1/dogs` | 내 반려견 목록 |
| PUT | `/api/v1/dogs/{id}` | 반려견 정보 수정 |
| DELETE | `/api/v1/dogs/{id}` | 반려견 삭제 |

### 장소 (Place)

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/v1/places` | 장소 목록 (region, type, congestion 필터 + 정렬) |
| GET | `/api/v1/places/{id}` | 장소 상세 |
| GET | `/api/v1/places/{id}/walk-courses` | 장소 주변 산책 코스 |

**목록 쿼리 파라미터:**
```
region=GANGNEUNG|CHUNCHEON|WONJU
type=STAY|WORK_PLACE|FOOD|TOUR|WALK|HOSPITAL
congestion=RELAXED|NORMAL|CROWDED|VERY_CROWDED|UNKNOWN
sort=PET_WORK_SCORE|LOW_CONGESTION|LATEST
page=0&size=20
```

### 코스 (Course)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/courses` | 코스 생성 요청 (사용자 조건 입력 → 코스 반환) |
| GET | `/api/v1/courses/{id}` | 코스 조회 |
| PUT | `/api/v1/courses/{id}` | 코스 편집 (순서, 시간, 장소 변경) |
| DELETE | `/api/v1/courses/{id}` | 코스 삭제 |
| POST | `/api/v1/courses/{id}/items/{itemId}/alternatives` | 대체 장소 추천 |

### 관심 장소 (Favorite)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/favorites/{placeId}` | 관심 장소 저장/해제 (토글) |
| GET | `/api/v1/favorites` | 내 관심 장소 목록 |

### 후기 (Review)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/reviews` | 후기 작성 |
| GET | `/api/v1/reviews?placeId={id}` | 장소별 후기 목록 |
| DELETE | `/api/v1/reviews/{id}` | 내 후기 삭제 |

### 배치 트리거 (Admin)

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/v1/admin/batch/collect` | 장소 수집 배치 실행 |
| POST | `/api/v1/admin/batch/congestion` | 혼잡도 수집 배치 실행 |

## 3. 구현 우선순위

### Phase 1 — 데이터 파이프라인 (배치)
> 앱 없이도 DB를 채울 수 있는 상태
1. `PlaceCollectJob` 실행 검증 (KTO + GWTO 수집)
2. `CongestionBatchJob` 구현 및 검증
3. Admin API로 배치 수동 트리거

### Phase 2 — 핵심 조회 API
> DB에 데이터가 있으면 바로 개발 가능
4. 장소 목록/상세 API (`/api/v1/places`)
5. 산책 코스 연결 API

### Phase 3 — 인증 & 사용자
6. 카카오 로그인 + JWT 발급
7. 반려견 프로필 CRUD

### Phase 4 — 코스 생성
8. 코스 생성 로직 (규칙 기반 또는 AI)
9. 코스 편집 + 대체 장소

### Phase 5 — 사용자 기능
10. 관심 장소 (Favorite)
11. 후기 (Review)

## 4. 인증 방식

- **카카오 OAuth 2.0** → Access Token으로 카카오 API 호출 → 사용자 정보 수집
- 서버에서 **자체 JWT** 발급 (accessToken 30분, refreshToken 14일)
- refreshToken은 **DB 저장** (users 테이블의 refresh_token 컬럼)
- **Redis 사용 안 함** (MVP): DB 저장으로 충분. 성능 이슈 발생 시 추후 도입

---

## 5. Redis 도입 기준

MVP에서는 Redis 없이 시작. 아래 조건 충족 시 도입:
- 동시 사용자 100명 이상으로 DB 부하 발생
- 장소 목록 캐싱이 실제로 필요한 수준의 트래픽
- 배치 분산 실행 환경으로 확장 필요 시

## 6. EC2 서버 초기 세팅 절차

```bash
# 1. Docker 설치
sudo yum update -y
sudo yum install docker -y
sudo systemctl start docker
sudo usermod -aG docker ec2-user

# 2. AWS CLI 설치 (ECR 로그인용)
sudo yum install awscli -y

# 3. 앱 디렉토리 생성
mkdir -p ~/app
cd ~/app

# 4. .env 파일 생성 (.env.example 참고)
vi .env   # 실제 값 입력

# 5. GitHub Actions가 자동으로 배포
# (첫 배포 전에 ECR 리포지토리 생성 필요)
```

### GitHub Actions 등록 필요 Secrets

| Secret 이름 | 설명 |
|---|---|
| `AWS_ACCESS_KEY_ID` | ECR push용 IAM 키 |
| `AWS_SECRET_ACCESS_KEY` | IAM 시크릿 |
| `ECR_REPOSITORY` | ECR 리포지토리 이름 (officemeong) |
| `EC2_HOST` | EC2 퍼블릭 IP 또는 도메인 |
| `EC2_USERNAME` | ec2-user |
| `EC2_SSH_KEY` | EC2 PEM 키 내용 |
